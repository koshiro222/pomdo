# 同期は匿名アカウント方式で行い、ゲスト移行ダイアログを廃止する

未ログインでの試用を許しつつマルチデバイス同期を提供するため、初回アクセス時にサーバ側で匿名ユーザーを作成する（Better Auth anonymous プラグイン）。すべての書き込みは最初からサーバDBに入り、「ログイン」は匿名アカウントを Google アカウントに結合する操作になる。旧実装の「localStorage に保存 → ログイン時にマイグレーションダイアログで手動移行」は廃止する。

## 背景

旧実装のゲストモードは、ゲスト→ログイン時に localStorage のデータをサーバへ1件ずつ移行しており、ToDo しか移行されず Pomodoro 履歴（統計データ）が失われていた。移行ダイアログ自体が UX の摩擦であり、バグの温床だった。

## 考えた代替案

- **ローカルファースト＋同期エンジン**（Replicache / Zero / PowerSync 等）: オフライン捕捉ができ ADHD ユーザーに理想的だが、同期エンジンの導入は新たな複雑さ＝負債になる。負債削減という作り直しの目的に反する。
- **移行処理を完全化して静かにする**: 二重管理は残り、根本解決にならない。

## 結果

- 初回アクセスに1回ネットワーク往復が要る。完全なオフライン利用は v1 では不可。
- 匿名アカウントは Cookie 上の識別子に紐付くため、Cookie 消去・別ブラウザではデータに到達できない。最終アクセスから90日で匿名データを削除するバッチを設ける。
- 体感速度は TanStack Query の楽観的更新で担保する。
- オフライン対応（ローカルファースト・ライト方式）は v1.x で別途検討する。
