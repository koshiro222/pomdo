# タイマーは絶対時刻方式で実装し、Web Worker / Service Worker を使わない

Focus Session の残り時間は「終了予定時刻（`endsAt`）から現在時刻を引く」方式で常に算出する。カウントダウン用の `setInterval` を Web Worker に逃がすこともしない。

## 背景

ブラウザは非アクティブなタブの `setInterval` / `setTimeout` を大幅に間引く（1 秒間隔が数十秒〜1 分に落ちる）。旧実装は `remainingSecs` をメインスレッドの `setInterval` で 1 秒ずつ減算しており、タブを離れると時間が「止まって」見え、戻ると大きくジャンプした。多くのタイマーアプリはこれを Web Worker や Service Worker で回避しようとする。

## 理由

- 残り時間を `endsAt - now` で毎回計算するなら、間引きは無関係になる。タブ非アクティブ中に描画が止まっても、復帰した瞬間に正しい残り時間（またはゼロ＝完了）が出る。
- Web Worker は新たなビルド設定・メッセージパッシング・状態の二重化を持ち込む。絶対時刻方式なら不要。
- `endsAt` はクライアント localStorage（Zustand persist）に保持し、`focus.start` RPC が返すサーバ時刻でオフセット補正するので、クライアント時計のズレにも耐える。

## 結果

- 描画は 1 秒間隔の `setInterval`（メインスレッド）で行い、各 tick で `endsAt - now` を再計算するだけ。間引かれても実害なし。円盤タイマーの角度も同じ計算から求める。
- タブ復帰時: `endsAt` を過ぎていて猶予（60 秒）以内なら完了扱い、超過なら「約 X 分の集中を記録しますか？」と確認する。
- 「精度のために Web Worker を入れよう」という PR が来たら、この ADR を差し戻し理由に使うこと。絶対時刻方式で解けない精度問題が具体的に示されない限り、Worker は入れない。関連: [[0005-no-timer-pause]]。
